# Route checks

1. Inspect supported API/connector operations and authenticated identity. Establish which submission, status, continuation or cancellation operations actually exist; a connected tool is not evidence of a complete dot lifecycle interface. Done when the requested operation and available scope match.

2. For a desktop-app route, apply the owner's launch/close policy and make a fresh app attempt when desktop-first is required. Verify the installed package/process, current window, account and existing conversation through authorized controls. Use one controller and current observations. Respect tool-specific denials; shell/UI automation is not a substitute for a prohibited peer tool. Done when the exact app target and permitted control are verified, or a concrete reason for browser fallback is recorded.

3. For a browser route, inspect profiles and existing tabs before opening a task-owned tab. Follow the installed browser-automation skill and verify account/conversation after navigation. Refresh references after rerendering; preserve unrelated tabs and dashboard foreground requirements. Done when current targets resolve to the intended conversation.

4. Inspect pending work and unsent composer text before replacement. Populate only the prepared scoped brief, read its complete content back, and compare before one dispatch. If filling settles asynchronously, reread current state instead of sending an uncertain composition. Done when the full composer matches and no unrelated pending input was displaced.

5. Retrieve the complete correlated reply. Use a scoped document/conversation read when broad observations truncate; distinguish an initial acknowledgment from the eventual verdict. Verify actual reported thread changes or artifacts independently where available. Done when the deliverable and source-inspection limits are established.

Use [peer-mailbox.md](peer-mailbox.md) only for the separate optional file branch. Neither these instructions nor a successful UI exchange establish unattended operation or grant access.
